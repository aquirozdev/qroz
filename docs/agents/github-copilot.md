# GitHub agents and repository instructions

Arc uses GitHub's current repository customization layers deliberately.

## Layering

### `AGENTS.md`

Cross-agent architectural rules. This is the broadest agent-facing source and should remain tool/vendor-neutral.

### `.github/copilot-instructions.md`

Always-on GitHub Copilot repository context: workflow, invariants and required reading.

### `.github/instructions/*.instructions.md`

Path-specific rules. Arc currently separates TypeScript and documentation rules so agents do not load irrelevant detail for every task.

### `.github/agents/*.agent.md`

Specialist Copilot agents:

- **Arc Architect** — design/research/ADR analysis;
- **Arc Implementer** — focused vertical-slice implementation;
- **Arc Reviewer** — semantic/portability/security review;
- **Arc Docs** — canonical documentation/research maintenance.

### `.github/skills/*/SKILL.md`

Task-specific reusable workflows loaded when relevant. Skills contain detail that would be wasteful as always-on instructions.

Current skills:

- architecture change;
- CI failure debugging.

## Rule against instruction sprawl

Do not copy the same rule into every agent file. Put:

- universal architectural rules in `AGENTS.md`;
- Copilot-specific workflow hints in `copilot-instructions.md`;
- file-scoped details in path instructions;
- specialist behavior in custom agents;
- repeatable task procedures in skills.

## Agent PR expectations

An agent-authored PR is held to the same gates as a human PR:

- focused issue/problem;
- public API example when relevant;
- tests and contracts;
- platform evidence;
- docs/ADR;
- green CI.

“Generated by an agent” is never evidence that a change is safe.
