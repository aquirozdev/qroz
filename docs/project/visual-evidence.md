# Visual product evidence

Arc treats user experience as executable behavior, not a collection of manually curated screenshots.

Browser-facing product claims should be backed by a reproducible journey that runs against the real Arc development server and Studio.

## Evidence model

A visual evidence scenario may produce:

- **browser acceptance assertions** — the merge gate;
- **deliberate screenshots** — stable review points for docs and product review;
- **video** — the complete browser journey;
- **Playwright trace** — actions, DOM snapshots, network activity and timing;
- **HTML report** — a browsable test report.

Screenshots and video supplement executable assertions. They do not replace them.

## First canonical journey

The initial scenario uses the real `examples/taskboard` application.

It:

1. starts `arc dev`;
2. opens Arc Studio in Chromium;
3. verifies application, module, route and capability information from the Application Graph;
4. executes `GET /tasks/task-1` through Studio's request runner;
5. verifies the application response, request activity and trace activity;
6. captures overview and post-request screenshots;
7. records the full video and Playwright trace.

The CI job uploads the resulting evidence as a GitHub Actions artifact.

## Reproducibility rules

Visual product evidence must:

- run against a real Arc application and runtime;
- use a pinned browser automation dependency;
- use a fixed viewport and browser project in CI;
- contain no secrets or production credentials;
- avoid dashboard-only setup or hidden fixture state;
- preserve the distinction between behavior assertions and pixel-level visual regression testing.

Pixel-diff baselines are a separate concern and should only become merge gates when their rendering environment is sufficiently deterministic.

## Documentation and marketing

Release documentation may promote verified screenshots or clips generated by these scenarios.

The source of a documentation or marketing asset should remain identifiable from its scenario and Arc release. Manual mockups must not be presented as product evidence.

## Planned scenarios

Add evidence journeys for:

- authorization denial and principal-claim redaction;
- full-process development reload;
- security/privilege semantic diff;
- provider-neutral deployment planning;
- durable workflow execution.
