# AWS v0.8 research baseline

Research date: **2026-09-19**.

## HTTP API

API Gateway HTTP API Lambda proxy integration supports payload formats 1.0 and 2.0. v2 exposes `rawPath`, `rawQueryString`, normalized headers and cookies.

Decision: Qroz's first AWS HTTP adapter targets payload format 2.0 and converts it at the boundary to a Web `Request`.

Source: https://docs.aws.amazon.com/apigateway/latest/developerguide/http-api-develop-integrations-lambda.html

## Lambda runtime lifecycle

AWS recommends reusing execution environments and initializing SDK clients/database connections outside the handler when safe, while avoiding user/session mutable state in globals.

Decision: Qroz provider lifecycle cannot assume every serverless provider is invocation-scoped. Platform composition should support both reusable clients and invocation-scoped disposable resources.

Source: https://docs.aws.amazon.com/lambda/latest/dg/best-practices.html

## SQS producer

Per-message `DelaySeconds` is 0–900 seconds for standard queues and is not supported per-message for FIFO queues. `SendMessageBatch` accepts at most 10 messages and can report partial failures even when the request succeeds.

Decision: the SQS adapter exposes delay only for non-FIFO queue capabilities, chunks batch sends into groups of ten and treats reported failed entries as an error.

Sources:
- https://docs.aws.amazon.com/AWSSimpleQueueService/latest/APIReference/API_SendMessage.html
- https://docs.aws.amazon.com/AWSSimpleQueueService/latest/APIReference/API_SendMessageBatch.html

## SQS consumer

Lambda event source mappings can enable `ReportBatchItemFailures`. A handler returns `batchItemFailures` containing failed SQS message IDs so successful messages are not needlessly retried.

Decision: Qroz's SQS consumer maps only `retry` outcomes into `batchItemFailures`; ack/discard/poison outcomes are omitted.

Source: https://docs.aws.amazon.com/lambda/latest/dg/services-sqs-parameters.html

## S3

AWS SDK v3 S3 GetObject bodies expose transformation helpers including Web Stream conversion.

Decision: Qroz's S3 storage adapter preserves Qroz's `ReadableStream<Uint8Array>` contract instead of forcing buffering.

Source: https://docs.aws.amazon.com/sdk-for-javascript/v3/developer-guide/javascript_s3_code_examples.html

## DynamoDB idempotency

Conditional PutItem using `attribute_not_exists` provides an atomic create-if-absent primitive. AWS Lambda guidance also recommends DynamoDB/TTL-backed idempotency for duplicate event handling.

Decision: DynamoDB is the leading AWS adapter candidate for Qroz's claim/lease/completion idempotency store. It must additionally use conditional updates for lease takeover/completion token ownership; a single PutItem alone is not sufficient for the full Qroz contract.

Sources:
- https://docs.aws.amazon.com/amazondynamodb/latest/APIReference/API_PutItem.html
- https://docs.aws.amazon.com/lambda/latest/dg/concepts-application-design.html

## Tracing

AWS supports X-Ray and AWS Distro for OpenTelemetry (ADOT) for Lambda.

Decision: Qroz should prefer an OpenTelemetry-compatible semantic bridge and avoid coupling core semantics to X-Ray-specific APIs.

Source: https://docs.aws.amazon.com/lambda/latest/dg/nodejs-tracing.html


## Local AWS emulation

Floci is an MIT-licensed AWS emulator that requires no account/token and currently covers Qroz's v0.8 needs: S3, SQS, DynamoDB, API Gateway v2 and Docker-backed Lambda execution. Stable Docker releases are versioned and can be pinned (Qroz CI uses `floci/floci:2.1.0`).

LocalStack remains a capable option, but its former Community edition was sunset in March 2026 and the unified image requires an account/auth token. For Qroz's zero-cost CI goal, Floci is currently the better default.

AWS SAM Local remains useful as a secondary fidelity check for Lambda/API Gateway because it runs Lambda functions in AWS-provided runtime images, but it does not replace an integrated S3/SQS/DynamoDB emulator.

Decision: use layered evidence:
1. Qroz unit/contract tests;
2. AWS SDK v3 + Floci as the default zero-cost integration gate;
3. SAM Local where Lambda/API Gateway runtime fidelity is specifically useful;
4. real AWS only for behaviors that emulators cannot establish, and not as a mandatory gate during early framework development.

Sources:
- https://github.com/apanner/floci_aws
- https://hub.docker.com/r/floci/floci
- https://blog.localstack.cloud/2026-upcoming-pricing-changes/
- https://docs.aws.amazon.com/serverless-application-model/latest/developerguide/using-sam-cli-local.html
