# Design proposals

These pages preserve important parts of Arc's product thesis that are not implemented yet.

A proposal is **not a compatibility promise**. It should describe:

- user problem;
- desired application-facing shape;
- semantic model implications;
- portability risks;
- security/operational constraints;
- evidence required before implementation;
- open questions.

When a proposal becomes an accepted architectural constraint, record the final decision in an ADR and update canonical reference docs.
